Telemetry · Logs

Logs — audit entries, dual-written · conversation content, OTLP-only

The logs signal carries two kinds of record. Audit entries are dual-written: OTEL Logs export to <endpoint>/v1/logs AND a local JSONL file at collector.logs.path (default ~/.nio/audit.jsonl). The JSONL line is the entry verbatim; the OTEL LogRecord uses body = JSON.stringify(entry) plus a flat attribute set for indexing. Content records carry the conversation itself and are OTLP-only.

The OTLP leg is gated; the local file is not

The logger provider is built only for a session someone armed with /nio-monitor on (/nio monitor on on OpenClaw and Hermes), or when collector.monitor_all_sessions: true. Until then nothing goes to /v1/logs and no content record is produced at all.

The local ~/.nio/audit.jsonl leg is never gated: guard decisions, skill scans, lifecycle and hook events are written to it whether or not the session was armed, because the file never leaves the machine and backs /nio report. It is controlled by collector.logs.local alone. See Capture gating.

OTEL LogRecord projection

The flat attribute set used for OTEL Logs indexing. Same key names as the matching trace span attributes wherever a concept overlaps (tool name, conversation id, guard decision, …) — same query keys work across logs and traces.

  • body = JSON-stringified entry (full content of the JSONL line)
  • severityNumber / severityText — always an OTel severity, never a nio risk level. severityText is one of INFO / WARN / ERROR / FATAL, and always the standard name of the record's own severityNumber
  • nio.risk_level — the nio risk level, when the entry has one

Severity and risk level are two different dimensions. severityNumber / severityText are the OTel log level, and backends build their severity facets and filters from the names the OTel logs data model defines. Nio's risk level (low / medium / high / critical) is a classification of the action, not of the log record, so it travels as its own attribute.

An entry without a risk level is INFO because nio reached no verdict on it — not because the verdict was "low". Filter on nio.risk_level, not on severity, to find low-risk actions.

Content records

The conversation itself — reasoning, replies, tool arguments, tool results — is split between the traces and the logs signal by size, not by kind. Small bodies ride on the span so a trace is readable on its own; large ones stay here, where there is no attribute ceiling and no cost to a trace query, and join back to their span by id.

ContentSpan sideLogs sideCap
Assistant reply (text)nio.chat.reply on the chat span — all text blocks of the call joined in ordera text record only when the reply exceeded the 2 KB budget64 KB
Tool arguments (tool_input)gen_ai.tool.call.arguments on the execute_tool spana tool_input record only when the arguments exceeded the budget (hook platforms); on the in-process platforms one record always, emitted at span open16 KB
Tool result (tool_output)hook platforms: never. In-process: a ≤2 KB copy as gen_ai.tool.call.resultalways a tool_output record32 KB
Reasoning (thinking)neveralways a thinking record64 KB

One body, one owner. A body is not on the wire twice. If nio.chat.reply is present and nio.content.truncated is absent, the span holds the whole reply and no text record was emitted for it. If nio.content.truncated is true, the span holds a preview and the log record — full fidelity, up to the configured per-kind limit — is authoritative. Redaction runs before truncation on both sides, so a secret straddling the cut point cannot be sliced in half past the redactor.

These records are OTLP-only — never written to the local audit.jsonl, and emitted only for a session armed with /nio-monitor. Caps are configurable via collector.content_limits.

A record is never emitted with an empty body. Emptiness is judged on the final body — after redaction, after truncation — and applies to every nio.content.type. A body that redaction reduced to [REDACTED], or that truncation reduced to the truncation marker, is not empty and is still emitted: both still say something happened.

How nio.content.fidelity is decided

A thinking block is only as useful as the reasoning it actually contains. Some models return their raw chain-of-thought; some APIs deliberately withhold it and return a step-level summary instead. Reading the second as if it were the first turns "the summary didn't mention risk X" into "the model didn't consider risk X". The verdict is therefore a property of the model — never of the platform tag, and never of the transport the call arrived over.

ValueMeaning
fullThe model returns its reasoning verbatim. Recognised families: Anthropic Claude (including routed ids such as us.anthropic.claude-opus-4-6-v1), DeepSeek, GLM/ChatGLM, Qwen/QwQ
summaryThe API withholds the raw chain-of-thought and returns a step-level narration. Recognised families: OpenAI's reasoning series (gpt-5*, o1/o3/o4, codex*, gpt-oss), Gemini thinking models
unknownNo rule recognised the model. Nio has no evidence either way — this is a real answer, not a placeholder for summary

On the three hosts that report a model id per call — Pi, opencode, OpenClaw — the verdict is taken from that model id, with the provider string as a fallback only. The other three do not need the lookup, because their session file only ever holds one model family: Claude Code is always full, Codex always summary, and Hermes decides per payload shape (an OpenAI-reasoning marker → summary; Anthropic-shaped thinking blocks → full; neither → no thinking block is fabricated at all).

Observed: no thinking records from Claude Code

In one session sampled on 2026-08-06, all 382 thinking blocks in the transcript had thinking: "" with only the signature populated — so that session produced no thinking content records at all. This is what the host wrote to its transcript, not something Nio drops: Nio reads the field the host provides.

Treat it as one measurement, not as a property of the platform. What a transcript carries can vary by model and by thinking level, and this project has already been wrong in exactly this way once (Codex was recorded as having no thinking text on the strength of an effort=medium sample; effort=high produced it). If you need to know whether reasoning is being captured on a given setup, measure that setup.

Local JSONL path: collector.logs.path (default ~/.nio/audit.jsonl). Rotation kicks in at collector.logs.max_size_mb (default 100 MB) — the live file is renamed to <path>.1. Content records never appear in it.
