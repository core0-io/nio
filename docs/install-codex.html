Install · Codex CLI

Install Nio for Codex CLI.

Download the platform zip, run setup.sh, and Nio registers a local marketplace + plugin in ~/.codex/config.toml, enables the codex_hooks feature flag, and writes default config to ~/.nio/.

Requirements

  • Codex CLI 0.128.0 (codex --version; the cask codex works on macOS — brew install --cask codex). Other versions may work but only 0.128.0 has been verified end-to-end.
  • Node.js ≥ 18 on PATH (the guard scripts are Node)
  • macOS or Linux

Install

One-liner

VERSION=$(curl -s https://api.github.com/repos/core0-io/nio/releases/latest | grep tag_name | cut -d'"' -f4) && \
curl -LO "https://github.com/core0-io/nio/releases/download/${VERSION}/nio-codex-${VERSION}.zip" && \
unzip -o "nio-codex-${VERSION}.zip" -d nio-codex && \
cd nio-codex && ./setup.sh

Manual

  1. Grab nio-codex-v<version>.zip from the Releases page.
  2. unzip nio-codex-v<version>.zip -d nio-codex
  3. cd nio-codex && ./setup.sh

If you use multiple agent platforms (Codex + Claude Code + OpenClaw + Hermes), grab nio-all-v<version>.zip instead — the bundled setup.sh auto-detects which agents you have and sets up all of them.

What setup.sh does

Codex 0.128 has no codex plugin install subcommand and never auto-installs from a registered marketplace, so setup.sh performs a full nuke + cp install on every run:

  1. Verifies Node.js ≥ 18 is on PATH and ~/.codex/ exists.
  2. Wipes and rewrites ~/.codex/plugins/cache/nio/nio/<version>/ from the unzipped plugin source (this is what Codex actually loads at session start).
  3. Wipes and rewrites ~/.nio/codex-marketplace/ with a Codex-valid marketplace catalog (.agents/plugins/marketplace.json + a mirror of the plugin dir).
  4. Writes a hooks.json into the cache dir with absolute paths — Codex runs hook commands with cwd = session-cwd, so plugin-relative ./skills/... paths can't resolve at runtime.
  5. Edits ~/.codex/config.toml in place (idempotent) to add:
    • [marketplaces.nio] pointing at ~/.nio/codex-marketplace
    • [plugins."nio@nio"] enabled = true
    • codex_hooks = true under [features] (stable; gates the global hook system)
    • plugin_hooks = true under [features] (still under-development in 0.128, but required for plugin-bundled hooks.json to load)
  6. Creates ~/.nio/ and writes config.yaml from the defaults (kept if it already exists, unless you pass --reset-config).

Dev iteration: after editing source files, re-run setup.sh — the nuke + cp cycle picks up everything fresh. No mtime tracking, no partial sync.

Release-zip robustness: the cache and marketplace dirs are full copies, so deleting the unzipped source dir afterward does not break the install.

Flags

FlagPurpose
--codex-home <path>Override the Codex config dir (default $CODEX_HOME, else ~/.codex).
--reset-configOverwrite ~/.nio/config.yaml with the bundled defaults. Use after upgrades that changed the schema.
--uninstallRemove the marketplace + plugin entries and ~/.nio/.
-h, --helpPrint usage.

Where things live

PathWhat
~/.nio/config.yamlGuard + collector config. See Config reference.
~/.nio/audit.jsonlAppend-only JSONL audit log: guard decisions, scans, lifecycle events. Read via $nio report in a Codex session.
~/.codex/config.tomlCodex's own config — Nio appends [marketplaces.nio], [plugins."nio@nio"], and toggles features.codex_hooks + features.plugin_hooks.
~/.codex/plugins/cache/nio/nio/<version>/Plugin install cache — what Codex actually loads. Recreated on every setup.sh run.
~/.nio/codex-marketplace/Generated marketplace catalog Codex reads to resolve the nio@nio plugin id. Recreated on every setup.sh run.
~/.codex/sessions/<date>/rollout-*.jsonlCodex transcript path passed to hooks via transcript_path. Used by the collector for span continuity.

Set NIO_HOME to move the config/audit log elsewhere (e.g. NIO_HOME=~/Projects/nio-state).

Verify

  1. Open a fresh Codex session (hooks take effect on the next session, not the one in flight).
  2. Trigger the skill explicitly: codex "$nio config show" — the current protection level and config path print.
  3. Try a scan: codex "$nio scan ."
  4. Make the agent run something benign (codex "list files in /tmp"), then codex "$nio report" — the event is there.
Skill trigger in Codex

Codex doesn't support custom slash commands like /nio — the skill is reachable via Codex's own skill-trigger conventions: type $nio to invoke explicitly, or describe what you want in natural language and Codex will pick the skill from SKILL.md.

Upgrade

Download the new zip, run ./setup.sh. Existing config is preserved. If the new version changed the schema, add --reset-config.

Uninstall

./setup.sh --uninstall

Removes [marketplaces.nio] + [plugins."nio@nio"] from ~/.codex/config.toml, wipes ~/.codex/plugins/cache/nio/, wipes ~/.nio/codex-marketplace/, and removes ~/.nio/. The features.codex_hooks and features.plugin_hooks entries are left intact (harmless when nio is gone). Safe to re-run.
